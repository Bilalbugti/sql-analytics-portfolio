# SQL Analytics Portfolio

A collection of realistic SQL queries against a synthetic retail-banking dataset (branches, customers, accounts, transactions) — covering window functions, CTEs, KPI/BI reporting logic, and data quality validation.

This mirrors the type of SQL work I do daily: building KPI dashboards, customer segmentation, SLA/compliance monitoring, and data quality checks on banking transaction data (Snowflake/Databricks in production — SQLite here for a zero-setup, fully runnable public demo).

## Dataset

A synthetic banking dataset generated by `data/setup_database.py`:

| Table | Description | Rows |
|---|---|---|
| `branches` | 5 branches across Pakistan regions | 5 |
| `customers` | Customer records with KYC status & signup date | 3,000 |
| `accounts` | Savings/Current/Fixed Deposit accounts per customer | ~4,500 |
| `transactions` | Deposits, withdrawals, transfers, payments | ~139,000 |

The generator intentionally seeds a small number of realistic data quality issues (a handful of accounts opened before their customer's signup date, high-value outlier transactions) — these are what the `04-data-quality-checks` queries are designed to catch, matching how validation actually gets built in production: against real, imperfect data.

## How to run

```bash
git clone https://github.com/YOUR-USERNAME/sql-analytics-portfolio.git
cd sql-analytics-portfolio

# Build the database (only needs to be run once)
python data/setup_database.py

# Then run any query file against it, e.g.:
sqlite3 data/banking_analytics.db < 01-window-functions/queries.sql
```

Or open `data/banking_analytics.db` in any SQLite client (DB Browser for SQLite, DBeaver, VS Code SQLite extension) and run the queries interactively.

## Portfolio structure

### [`01-window-functions/`](01-window-functions/queries.sql)
Ranking customers per branch, running monthly totals, month-over-month growth (`LAG`), and latest-record-per-group patterns (`ROW_NUMBER`).

### [`02-cte-and-subqueries/`](02-cte-and-subqueries/queries.sql)
Customer activity segmentation, above-average value detection (correlated subqueries), dormant account detection, and multi-account "customer 360" views.

### [`03-kpi-reporting/`](03-kpi-reporting/queries.sql)
Branch performance scorecards, KYC compliance breakdown, SLA-style overdue monitoring, channel mix (digital adoption), and customer acquisition trends — the exact query style that feeds a Power BI/Tableau dashboard.

### [`04-data-quality-checks/`](04-data-quality-checks/queries.sql)
Referential integrity checks, duplicate detection, business-rule validation on transaction amounts, and a single consolidated "data health" summary query.

## Tech stack

SQL (SQLite dialect for portability — window functions, CTEs, and aggregate patterns shown here translate directly to Snowflake, Postgres, or SQL Server with minimal syntax changes).
